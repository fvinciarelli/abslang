## The tool round-trip: three Behaviors

```yaml
# 1. Agent calls the tool
- actor: assistant
  action: calls
  target: Orders API
  with:
    orderId: "8291"

# 2. Tool responds
- actor: tool
  action: responds
  target: Orders API
  content:
    orderId: "8291"
    status: "in_transit"

# 3. Agent tells the user
- actor: assistant
  action: informs
  content: "Your order is on its way."
```

Why three steps? QA checks each independently: parameters, payload, communication.

---

## `with` vs `with_only`

**`with`** — partial match. Extra params OK. Default.

```yaml
with:
  orderId: "8291"
# Agent can add locale, tracingId — no problem
```

**`with_only`** — strict match. No extra keys allowed.

```yaml
with_only:
  orderId: "8291"
  amount: 47.50
# Any extra parameter → mismatch
```

Use `with_only` for security-critical or compliance-sensitive calls.

## Multiple tool calls

```yaml
- actor: assistant
  action: calls
  target: Orders API
- actor: assistant
  action: calls
  target: Inventory API
  evaluations:
    - type: tool_call
      ordered: false    # both must happen, any order
```

Default is `ordered: true`. Set `ordered: false` for independent batched calls.

## Variables

```yaml
- actor: user
  action: says
  content: "Order 8291"
  capture:
    orderId: "8291"

- actor: assistant
  action: calls
  target: Refunds API
  with:
    orderId: "{{orderId}}"   # resolved to "8291"
```

Your agent doesn't need to know about ABS variables. The runner resolves them before comparing against your output.

## What your agent needs

One HTTP endpoint, OpenAI chat format:

```
POST /chat
Content-Type: application/json
{ "messages": [{"role": "user", "content": "Where is my order?"}] }
```

Response with tool calls:

```json
{
  "message": {
    "role": "assistant",
    "tool_calls": [{
      "function": { "name": "Orders API", "arguments": "{\"orderId\":\"8291\"}" }
    }]
  }
}
```

`target` in the spec is matched against `function.name`. Keep names aligned.

## Supported formats

| Format | Protocol |
|---|---|
| `openai` | OpenAI Chat Completions |
| `claude` | Anthropic Messages |
| `gemini` | Google Gemini |

Custom protocols: write a thin adapter implementing `send(messages) → response`.

## Schema validation on tool responses

```yaml
- actor: tool
  action: responds
  evaluations:
    - type: schema
      schema:
        type: object
        required: [orderId, status]
        additionalProperties: false
```

Catches API contract drift before production.

---

## How it runs

```
Parse YAML → for each Behavior:
  user says    → POST to /chat
  asst calls   → match tool_calls
  tool responds → send result back, continue
  asst informs → match response
→ Run all evaluations → Report pass/fail
```

The spec is your acceptance criteria. You're done when it's green.

## CI integration

```bash
abs run sessions/ --agent $STAGING_URL --format junit --ci > report.xml
```

JUnit output works with GitHub Actions, GitLab CI, Jenkins.

---

## Backend integration

ABS doesn't care how you implement tool calls. Use MCP, REST, function calling, or custom orchestration — as long as `tool_calls` matches the spec, you're good.
