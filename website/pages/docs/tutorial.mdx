## What ABS is and why it matters

A dev tells you *"the refund bot is ready, test it."* How do you know it's correct? Today you probably have test cases in a doc and you run through them manually. ABS replaces that: **one YAML file that describes behavior and runs as an automated test.**

In a Three Amigos session, this is the artifact QA, Dev, and PO all sign off on.

---

## Basic structure

```yaml
session: Customer checks order status
behaviors:
  - actor: user
    action: says
    content: "Where is my order #8291?"
  - actor: assistant
    action: calls
    target: Orders API
  - actor: assistant
    action: informs
    content: "Your order is on the way"
```

Three fields per step: `actor` (who), `action` (what they do), `content`/`target` (details).

## A real example: refund for damaged item

PO story: *"Customer reports damaged item. Agent verifies, processes refund, informs."*

### Step 1: The conversation

```yaml
session: Refund — damaged item
behaviors:
  - actor: user
    action: says
    content: "I received order #8291 damaged, I want to return it"
  - actor: assistant
    action: asks
    content: "I'm sorry about the damage. Can you confirm your name and order date?"
  - actor: user
    action: says
    content: "Franco Vinciarelli, ordered last Tuesday"
  - actor: assistant
    action: calls
    target: Orders API
    with:
      orderId: "8291"
  - actor: tool
    action: responds
    target: Orders API
    content:
      orderId: "8291"
      status: "delivered"
      eligibleForRefund: true
  - actor: assistant
    action: calls
    target: Refunds API
    with:
      orderId: "8291"
      reason: "damaged"
  - actor: tool
    action: responds
    target: Refunds API
    content:
      refundId: "R-5512"
      amount: 47.50
      status: "processed"
  - actor: assistant
    action: informs
    content: "Refund of €47.50 processed, Franco. You'll receive it in 3-5 days. Reference: R-5512."
```

PO understands it. Dev knows what to build.

### Step 2: Step-level evaluations

Two critical moments: the agent asks for verification, and the agent delivers the result.

```yaml
  - actor: assistant
    action: asks
    evaluations:
      - type: llm_judge
        criteria: |
          1. Shows empathy for the damaged item
          2. References the order number #8291
          3. Asks for verification info before taking action

  - actor: assistant
    action: informs
    evaluations:
      - type: contains
        value: "R-5512"              # hard fact
      - type: llm_judge
        criteria: |                   # soft qualities
          1. States amount and timeline
          2. Provides refund reference
          3. Uses customer's name
          4. Reassuring tone, no upsells
```

### Step 3: Chain evaluations

```yaml
evaluations:
  - type: sequence
    order:
      - { actor: assistant, action: asks }
      - { actor: assistant, action: calls, target: "Orders API" }
      - { actor: assistant, action: calls, target: "Refunds API" }
      - { actor: assistant, action: informs }

  - type: variable_consistency
    variable: refundId

  - type: never
    match: { actor: assistant, action: hands_off }
```

`sequence` checks ordering. `variable_consistency` catches ID drift. `never` is a safety guard.

## How to run it

**Browser:** [ABS Designer](/abs-designer/) — paste YAML, enter agent URL, ▶ Run.

**Terminal:** `abs run session.abs.yaml --agent http://localhost:8080/chat`

**VSCode:** Open `.abs.yaml`, editor panel opens. ▶ Run.

## Action vocabulary

| Category | Actions |
|---|---|
| Communication | `says`, `asks`, `informs`, `greets`, `clarifies`, `confirms`, `rejects`, `suggests`, `shows` |
| Execution | `calls`, `submits`, `retrieves`, `stores`, `updates` |
| Interaction | `selects`, `uploads`, `approves` |
| Delegation | `hands_off` |

---

## Evaluation types

| Evaluator | What it checks |
|---|---|
| `contains` | Text includes substring |
| `exact_match` | Text equals exactly |
| `regex` | Text matches pattern |
| `schema` | Payload validates against JSON Schema |
| `llm_judge` | Qualitative criteria (tone, empathy) |
| `sequence` | Steps in order |
| `eventually` | Something happens at least once |
| `never` | Something NEVER happens |
| `count` | Something happens N times |
| `within` | A happens within N steps of B |
| `variable_consistency` | A value stays unchanged |

## The Three Amigos session

**15 min** — Write the sequence. No evaluations.

**15 min** — Add step evaluations. *"What could go wrong? How do we verify?"*

**15 min** — Add chain evaluations. *"What must be true about the whole trace?"*

**15 min** — Review and sign off. One file, three perspectives.

---

## Common mistakes

| Mistake | Fix |
|---|---|
| Used `says` for an API call | Use `calls` + `target` |
| `sequence` fails but steps are there | It checks relative order, not adjacency |
| Want branching inside a session | v0.1: one path = one session |
| `llm_judge` inconsistent | Be specific in criteria |
